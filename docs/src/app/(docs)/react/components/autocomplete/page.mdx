## Usage guidelines

- **Avoid when selection state is needed**: Use [Combobox](/react/components/combobox) instead of Autocomplete if the selection should be remembered and the input value cannot be custom. Unlike Combobox, Autocomplete's input can contain free-form text, as its suggestions only _optionally_ autocomplete the text.
- **Can be used for filterable command pickers**: The input can be used as a filter for command items that perform an action when clicked when rendered inside the popup.
- **Form controls must have an accessible name**: It can be created using a `<label>` element or the `Field` component. See the [forms guide](/react/handbook/forms).

## Anatomy

Import the components and place them together:

```jsx title="Anatomy"
import { Autocomplete } from '@base-ui/react/autocomplete';

<Autocomplete.Root>
  <Autocomplete.InputGroup>
    <Autocomplete.Input />
    <Autocomplete.Trigger />
    <Autocomplete.Icon />
    <Autocomplete.Clear />
    <Autocomplete.Value />
  </Autocomplete.InputGroup>

  {/* A default AssistiveHint is rendered automatically. Include this part only to customize it. */}
  <Autocomplete.AssistiveHint />

  <Autocomplete.Portal>
    <Autocomplete.Backdrop />
    <Autocomplete.Positioner>
      <Autocomplete.Popup>
        <Autocomplete.Arrow />

        <Autocomplete.Status />
        <Autocomplete.Empty />

        <Autocomplete.List>
          <Autocomplete.Row>
            <Autocomplete.Item />
          </Autocomplete.Row>

          <Autocomplete.Separator />

          <Autocomplete.Group>
            <Autocomplete.GroupLabel />
          </Autocomplete.Group>

          <Autocomplete.Collection />
        </Autocomplete.List>
      </Autocomplete.Popup>
    </Autocomplete.Positioner>
  </Autocomplete.Portal>
</Autocomplete.Root>;
```

## TypeScript inference

Autocomplete infers the item type from the `items` prop passed to `<Autocomplete.Root>`.
If using `itemToStringValue`, the value prop on the `<Autocomplete.Item>` must match the type of an item in the `items` array.

### Grouped

Organize related options with `<Autocomplete.Group>` and `<Autocomplete.GroupLabel>` to add section headings inside the popup.

Groups are represented by an array of objects with an `items` property, which itself is an array of individual items for each group. An extra property, such as `value`, can be provided for the heading text when rendering the group label.

```tsx title="Example"
interface ProduceGroupItem {
  value: string;
  // @highlight
  items: string[];
}

const groups: ProduceGroupItem[] = [
  {
    value: 'Fruits',
    // @highlight
    items: ['Apple', 'Banana', 'Orange'],
  },
  {
    value: 'Vegetables',
    // @highlight
    items: ['Carrot', 'Lettuce', 'Spinach'],
  },
];
```

### Auto highlight

The first matching item can be automatically highlighted as the user types by specifying the `autoHighlight` prop on `<Autocomplete.Root>`. Set the prop's value to `"always"` if the highlight should always be present, such as when the list is rendered inline within a dialog.

The prop can be combined with the `keepHighlight` and `highlightItemOnHover` props to configure how the highlight behaves during mouse interactions.

### Command palette

Use the autocomplete input to filter a list of command items that perform an action when clicked. Render the list inline inside a [Dialog](/react/components/dialog) by combining `inline` with `open` on `<Autocomplete.Root>`, and pair it with `autoHighlight="always"` so the first result is ready to activate with <kbd>Enter</kbd>.

Because a modal `<Dialog.Popup>` renders a native [`<dialog>`](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/dialog) promoted to the browser's [top layer](https://developer.mozilla.org/en-US/docs/Glossary/Top_layer), position the popup itself (for example `position: fixed`)—don't wrap it in `<Dialog.Viewport>`, which only positions non-modal dialogs.

There's no need to add a keyboard-hint description to the input: `<Autocomplete.Root>` renders the default [assistive hint](#accessibility) automatically.

#### Memoizing items

Memoizing each item is a simpler alternative to virtualization for datasets up to roughly 1,000 items. Wrap each item in [`React.memo`](https://react.dev/reference/react/memo) and pass the item as a prop so unchanged items skip re-rendering. While memoization speeds up typing, it does not speed up opening; with a large enough number of items, the mount cost dominates, and virtualization becomes necessary to keep the open interaction fast on low-end devices.

```tsx title="Memoizing list items"
interface Suggestion {
  id: string;
  label: string;
  description: string;
}

const SuggestionItem = React.memo(function SuggestionItem({ item }: { item: Suggestion }) {
  return (
    <Autocomplete.Item value={item}>
      <span>{item.label}</span>
      <span>{item.description}</span>
    </Autocomplete.Item>
  );
});

<Autocomplete.List>
  {(item: Suggestion) => <SuggestionItem key={item.id} item={item} />}
</Autocomplete.List>;
```

### Minimum query length

Require a few characters before suggesting options using the `minLength` prop. While the query is
shorter than `minLength`, the list stays empty and `<Autocomplete.Status>` prompts the user to type
more.

```tsx title="Minimum query length"
<Autocomplete.Root items={items} minLength={3}>
  <Autocomplete.Input />
  <Autocomplete.Portal>
    <Autocomplete.Positioner>
      <Autocomplete.Popup>
        {/* Announces "Type 3 or more characters for results." while the query is too short. */}
        <Autocomplete.Status />
        <Autocomplete.List>
          {(item) => <Autocomplete.Item value={item}>{item}</Autocomplete.Item>}
        </Autocomplete.List>
      </Autocomplete.Popup>
    </Autocomplete.Positioner>
  </Autocomplete.Portal>
</Autocomplete.Root>
```

### Progressive enhancement

For a small, known list of options, render a `<select>` on the server and enhance it into an
autocomplete on the client. This keeps the field usable before JavaScript loads and preserves native
form submission.

```tsx title="Enhancing a <select>"
'use client';
import * as React from 'react';
import { Autocomplete } from '@base-ui/react/autocomplete';

function EnhancedSelect({
  name,
  label,
  options,
  defaultValue = '',
}: {
  name: string;
  label: string;
  options: { value: string; label: string }[];
  defaultValue?: string;
}) {
  const [enhanced, setEnhanced] = React.useState(false);
  const [value, setValue] = React.useState(
    () => options.find((option) => option.value === defaultValue)?.label ?? '',
  );

  // Enhance only after hydration so the native <select> works without JavaScript.
  React.useEffect(() => setEnhanced(true), []);

  const selectedValue = options.find((option) => option.label === value)?.value ?? '';

  if (!enhanced) {
    return (
      <label>
        {label}
        <select name={name} defaultValue={defaultValue}>
          <option value="">Select…</option>
          {options.map((option) => (
            <option key={option.value} value={option.value}>
              {option.label}
            </option>
          ))}
        </select>
      </label>
    );
  }

  return (
    <React.Fragment>
      {/* Submit the option's value, not its visible label. */}
      <input type="hidden" name={name} value={selectedValue} />
      <Autocomplete.Root
        items={options.map((option) => option.label)}
        value={value}
        onValueChange={setValue}
        autoHighlight
      >
        <label>
          {label}
          <Autocomplete.Input />
        </label>
        <Autocomplete.AssistiveHint />
        <Autocomplete.Portal>
          <Autocomplete.Positioner>
            <Autocomplete.Popup>
              <Autocomplete.Status />
              <Autocomplete.List>
                {(label: string) => (
                  <Autocomplete.Item key={label} value={label}>
                    {label}
                  </Autocomplete.Item>
                )}
              </Autocomplete.List>
            </Autocomplete.Popup>
          </Autocomplete.Positioner>
        </Autocomplete.Portal>
      </Autocomplete.Root>
    </React.Fragment>
  );
}
```

## Accessibility

- **Role**: `<Autocomplete.Input>` renders `role="combobox"`, and `<Autocomplete.List>` renders `role="listbox"` (or `role="grid"` in grid layouts).
- **Virtual focus**: focus stays on the input while navigating the list. The highlighted item is communicated through `aria-activedescendant` on the input rather than by moving DOM focus, so items never receive `aria-selected`—Autocomplete doesn't track a persisted selection the way [Combobox](/react/components/combobox#accessibility) does.
- **Keyboard interactions**:
  - <kbd>ArrowDown</kbd> / <kbd>ArrowUp</kbd> — opens the popup if closed, then moves the highlight
    between items, looping by default.
  - <kbd>Enter</kbd> — fills the input with the highlighted item.
  - <kbd>Escape</kbd> — closes the popup.
  - Typing filters the list; `mode` controls the value of `aria-autocomplete` (`list`, `both`, `inline`, or `none`).
- **Labeling**: the input needs an accessible name via `<label>`, `Field`, or `aria-label`—see [Usage guidelines](#usage-guidelines) above. `<Autocomplete.GroupLabel>` names its `<Autocomplete.Group>` through `aria-labelledby`. Keep `<Autocomplete.Status>` and `<Autocomplete.Empty>` mounted—they're `aria-live="polite"` regions that announce result counts and empty states.
- **Ready-made announcements**: `<Autocomplete.Status>` announces the number of available results, the highlighted option ("_Apple 1 of 8 is highlighted_"), empty states, and—when `minLength` is set on the root—a prompt to type more characters. Provide `children` to override the content entirely, or pass the `messages` prop to localize the generated strings.
- **Assistive hint**: a visually hidden instruction (how to operate the list with the keyboard) is included **by default** and associated with the input via `aria-describedby`. The association is removed automatically after the first keystroke to reduce screen reader verbosity. Render `<Autocomplete.AssistiveHint>` only to customize or translate the text—doing so replaces the default hint.

This pattern loosely follows the [ARIA APG Combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/). The assistive hint and status announcements are inspired by GOV.UK's [accessible-autocomplete](https://github.com/alphagov/accessible-autocomplete).
